# Проект

DocApprove помогает командам и организациям согласовывать документы.

## Словарь

- **Компания** — владелец рабочего пространства.
- **Организация** — рабочее пространство компании.
- **Документ** — файл или запись, проходящая согласование.

## Жёсткие правила

- Каждая новая таблица получает RLS-политики в той же миграции.
- Секретные ключи не попадают в браузер, Git или логи.
- `SUPABASE_SECRET_KEY` используется только на сервере и в скриптах.
- Публичные данные читаются через Supabase-клиенты с проверкой RLS.
- Уже применённые миграции не изменяются: добавляется новая миграция.
- Пользовательские тексты выносятся из компонентов в файлы переводов.
- Не добавлять Docker, локальный Postgres или Xcode без отдельной необходимости.

## Команды

```bash
npm install
npm run dev
npm run lint
npm run typecheck
npm run build
npm run seed
npm run test:security
```

## Структура данных

- Миграции: `supabase/migrations/`.
- Клиенты Supabase: `lib/supabase/`.
- Скрипты проверки и демо-данных: `scripts/`.

## Грабли

- Для production-переменных Vercel нужно настроить все значения из `.env.example` отдельно для нужных окружений.
- `SUPABASE_SECRET_KEY` нельзя использовать в client components.
